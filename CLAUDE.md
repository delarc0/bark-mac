# Bark-Mac: Claude Code context

Bark2 (ships as Bark 1.0.0 over 0.2.3). PRD, decisions and every measurement live in `tasks/bark2.md`; read its "Problems to solve", "Architecture" and "Lessons that become tests" first. Private repo: `github.com/delarc0/bark-mac`. Author Erik `<erik@lab37.io>`.

- `BarkKit/` is one Swift package (tools 6.2, macOS 26, Swift 6, deps pinned exact, `Package.resolved` committed):
  - `BarkCore`, pure and dependency-free: `Routing` (KB only on explicit `sv` or a fresh detection of >= 1 s and >= 0.85; a remembered language prefills, never routes), `TextCleanup`, `SegmentCut` (28 s cut), `CallRules` (call-app classification, the two-stream `BlockAligner`, `TapSilence`), `SpeakerAttribution` (a segment gets the diarized speaker with the largest overlap; Speaker 1...n by first appearance), `SegmentSplit` (where a segment holding two people is cut: stretches of at least 1 s, the quietest point near the change, pieces under 1 s join a neighbour, pieces must keep 90% of the words).
  - `BarkEngine`: MLX Whisper (`Whisper`, `Engine` = decode policy; `transcribe` takes an optional initial prompt, S6's vocabulary spike), own `Vocabulary` from tokenizer.json (id lookups, the byte-level decode, and the byte-level BPE encode for prompts; the vendored swift-transformers encode is wrong for KB), language detection, `ModelStore` (manifests, checksummed download), `Transcriber` actor (general model plus Swedish loaded in the background; all MLX work on one serial queue, 20 s decode timeout, MLX's buffer cache capped at 256 MB (`mlxCacheLimit`: a meeting peaks at 4.9 GB instead of 6.5); dictation goes first: its decodes jump queued background ones, and background decodes (meetings, recovery, the speaker pass) do not start while a DictationSession is open; a decode already running finishes), `Segmenter` (one stream's Silero segmentation, shared), `DictationSession` (one per key press: language pinned per dictation; `cancel()` abandons it), `MeetingSession` (one per meeting: explicit language, streams me/them/room each with its own Segmenter, decodes oldest first and commits each segment to BarkStore as decoded; `finish()` marks done, queues for hq, archives audio; `recover(id)` resumes an unfinished meeting from its PCM past the last committed segment per stream; `markGap`), `MeetingDiarizer` (S5: pyannote community-1 via FluidAudio's offline pipeline, a pass after a meeting is done: diarizes them/room from the archived audio, a call's me stream is `Me` undiarized, given the Transcriber it cuts segments holding two people and re-decodes the pieces with the segment's model and language, keeping the segment whole if any piece fails; saves speakers and re-queues for hq; models built straight from the folder it is given). Silero and the diarizer load from folders Bark gives them, never from FluidAudio's download path.
  - `BarkStore` (SDK only: SQLite3, AVFoundation): `MeetingStore` at `~/Library/Application Support/Bark/Meetings/` (`bark.sqlite`, WAL, synchronous FULL, schema by `user_version`; one folder per meeting). Tables meetings (v3: `diarization` pending | running | done | failed; finish sets pending; running at launch = cut short by a crash, marked failed, never retried), segments, speakers, notes (the user's own), gaps, outbox (hq push queue: pending | acknowledged | rejected, a generation bumped by every enqueue so a result for an older upload is ignored, last_attempt_at for backoff across relaunches). `PCMWriter` appends each stream as 16 kHz 16-bit PCM, fsync every 2 s of audio; at finish it becomes ALAC `<stream>.caf`, frame-checked, PCM deleted; `deleteExpiredAudio` (default 30 days) keeps transcripts. Dictation's never-on-disk rule does not apply to meetings.
  - `BarkCapture`: `MicCapture` (AVAudioEngine to 16 kHz mono chunks on an `AsyncStream`, device by UID, rebuilds on reconfiguration or a rate change), `AudioInputs`. Meetings: `SystemAudioTap` (Core Audio process tap, mono mixdown, per call app or global minus Bark, private aggregate device), `CallCapture` (mic with voice processing for echo cancellation plus the tap, aligned 100 ms me/them blocks, gap and tapSilent events), `AudioApps` (processes using audio). Its pure rules live in BarkCore `CaptureRules` (`ChannelSelector`: lowest channel at speech level, so loopback cannot hold it; `InputHealth`: digital silence = dead, zero callbacks = transient; `LegacySettings`). `capture-probe` is the S4 desk-test CLI; running it triggers the permission prompts.
  - `BarkHQ` (Foundation + Security): `HQSettings` (base URL empty = off, device token in the Keychain), `HQPairing` (zero-typing pairing through the `bark://hq-connected` callback, single-use nonce, 10 min), `HQUploader` (drains the outbox with an idempotent PUT, backoff 1 min to 6 h, 401 = reconnect, 413/422 = rejected, deletions sync). The server contract for lab-hq is `tasks/bark-hq-api.md`.
  - `mlx-eval`: the eval CLI on BarkEngine (engine-only, `--prompts` = per-clip initial prompts from a JSON map, `--pipeline`, `--realtime 1`, `--language auto`, `--meeting` = the S7 budget: a two-stream Swedish call from eval clips fed at `--speed` x real time; its store lives in `eval/meeting/store`; `--diarize` = every .wav through MeetingDiarizer with the bundled models, one RTTM each, S5's AMI set in `eval/ami`; `--split-eval` = one recording through a meeting and the speaker pass with and without splitting). `bark-eval`, `stream-eval`, `fluid-eval` are frozen spike tools on WhisperKit.
- Build and test: `cd BarkKit && swift build && swift test`. Tests that need models or eval clips skip when they are absent.
- App (`App/`): thin AppKit/SwiftUI on BarkKit. `Dictation` (press: `MicCapture` feeds a `DictationSession`, created only once the hold passes 200 ms; release: finish, paste; 300 s hard stop; an abandoned dictation is cancelled, never finished), `HotkeyMonitor` (listen-only tap, device-specific modifier masks, re-enable plus key-state re-check), `Paste` (Cmd-V with V resolved from the current layout, ConcealedType, 150 ms restore unless changeCount moved), `Models` (ModelStore readiness, download, Transcriber lifecycle; Silero loads straight from the bundled `App/Resources/silero-vad`; the diarization models are bundled in `App/Resources/speaker-diarization`, CC-BY-4.0 with their NOTICE), `Overlay/`, `MenuBarController`, `Settings/`, `Onboarding/`, `Updater` (Sparkle, Release only). `Meetings/`: `MeetingRecorder` (Start/Stop from the menu or an accepted offer; CallCapture into a MeetingSession, idle-sleep assertion, sleep = gap plus capture rebuilt on wake, finished on quit within 15 s), `CallWatcher` (5 s poll while idle, offers a call once per pid set, never records), `MenuBarPanel` (non-activating offer and notice panel), `NotebookWindow` (one grouped meeting history and notes window, with inline titles, recording controls, live transcript, speaker naming, delete, and rejected hq upload with Try Again), `NoteEditor` (TextKit 2 plain Markdown notes with live styling over BarkCore `NoteMarkup`: markers collapsed, `NoteLayout` draws bullets and checkboxes in the gutter, the caret never rests inside a marker), `MeetingLibrary` (store, launch recovery, speakers one meeting at a time after finish, recovery and launch, daily audio retention), `HQLink` (pairing via `bark://hq-connected` registered as an Apple Event handler, uploads and deletions sync); their pure rules are BarkCore `MeetingRules`.
- Build the app: `xcodegen && xcodebuild -project Bark.xcodeproj -scheme Bark -configuration Debug -derivedDataPath build build` (signing as below, Debug re-signs ad-hoc). Debug is "Bark Dev", `se.lab37.bark.mac.dev`, its own UserDefaults domain and TCC grants, Sparkle off; Release is "Bark", `se.lab37.bark.mac`, Sparkle feed and EdDSA key as 0.2.x. Release reads 0.2.x's hotkey, device UID and language keys; every other setting lives under new `bark2.*` keys. `install.sh` builds and installs Bark Dev to `~/Applications`; `scripts/release.sh` is the only release path. An app build writes Sparkle's pin into `BarkKit/Package.resolved` (Xcode uses it as the workspace's resolved file); do not commit that, `swift package resolve` in BarkKit puts it back.
- Models: `~/Library/Application Support/Bark/Models/<id>/{config.json,weights.safetensors,tokenizer.json}`, ids `kb-whisper-large[-8bit]` and `whisper-large-v3[-8bit]`. Not published yet (manifest URLs are a placeholder); `BarkKit/scripts/dev-models.sh` links the local eval conversions into that layout and makes the 8-bit large-v3 with `scripts/quantize.py`. 8-bit is the default (P1a: same WER as fp16, half the memory).
- Eval: `BarkKit/eval/p1a.sh [fp16] [q8]` runs every set through `DictationSession` and gates against `eval/baseline-mlx.json`; `eval/mlx.sh` is the engine-only S8 run. Data and results stay outside git in `~/Library/Application Support/Bark/eval`. Timings only count on a full-power charger.

## Conventions

- No code comments unless genuinely non-obvious (a hidden invariant, a workaround for a specific bug), one line.
- XcodeGen: `project.yml` is the source of truth; `Bark.xcodeproj` and `App/Info.plist` are generated and gitignored.
- Language prefill and model routing are two different decisions; never re-merge them. A remembered language prefills the general model, it never routes to KB (KB-Whisper silently translates English into Swedish).
- **Signing:** `project.yml` compiles ad-hoc (`CODE_SIGN_IDENTITY: "-"`) so a clean checkout builds on any Mac and the SPM targets never demand a development team. The Debug post-build phase deep-re-signs the bundle to unify nested Team IDs and, when `BARK_SIGN_IDENTITY="Bark Dev"` is passed (the optional self-signed cert from `scripts/create-signing-cert.sh`), upgrades to it so TCC grants survive rebuilds. Never pass `CODE_SIGN_IDENTITY` on the xcodebuild CLI: it leaks to the SPM targets and fails the build. Ad-hoc builds reset permissions on each rebuild.
- **Release:** `scripts/release.sh X.Y.Z [--publish]` is the only release path (preflight, bump, archive, Developer ID export per `distribution/ExportOptions.plist`, notarize, staple, verify, Sparkle-sign, appcast, GitHub Release, gh-pages). It refuses unless on a clean `main` equal to `origin/main`; `--check` probes machine readiness. The appcast item carries `sparkle:minimumSystemVersion` 26.0. Runbook: `distribution/README.md`.
